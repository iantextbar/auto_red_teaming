## Stated by the source

### What it is about

The paper studies the security of code generated by five open LLMs from the 148 unique prompts of the LLMSecEval benchmark (p. 3). Its object is not only how often generated code is vulnerable but how vulnerabilities cluster inside the same snippet and which prompt features bring them about (p. 1). It pursues three research questions: how well security-oriented metamorphic relations detect vulnerabilities (RQ1), which co-violation patterns emerge (RQ2), and which prompt characteristics predict the vulnerability burden (RQ3) (p. 1). It is addressed to researchers in software security and LLM code generation.

### Argument

The paper starts from the premise that security is a cross-cutting property of software, so failures in authentication, credential handling, input validation, file handling and memory safety may co-occur in one artifact, whereas most evaluations treat each vulnerability category in isolation (p. 1). Measuring only whether a snippet is vulnerable therefore misses how vulnerabilities cluster and why certain prompts repeatedly induce broader risk (p. 1).

To get a detection signal without a test oracle, it defines **nine security-oriented metamorphic relations** (MRs), each pairing an adversarial transformation with an expected secure output relation, for CWE-89, 79, 78, 22, 862, 798, 327, 120 and 190 (p. 2, p. 3). An LLM judge (Claude Sonnet 4.6) reasons statically about each snippet and returns applicability, a verdict (violated, pass, N/A) and a one-sentence evidence for all nine MRs at once (p. 2). The judge's verdicts form a violation matrix in which each snippet is a transaction and each violated MR an item.

The second move applies **Apriori association-rule mining** to that matrix, using support, confidence and lift (lift above 1 meaning co-occurrence beyond independence) (p. 2). From 44 rules it identifies two clusters: authentication, credential and cryptography (MR5, MR6, MR7), and input handling and memory safety (centred on path traversal and buffer overflow, with command injection added in the RQ3 and conclusion definitions), plus a bridging rule (p. 3, p. 4, p. 6). Hard-coded credentials are described as a "hub" linking input-validation failures to cryptographic weakness (p. 4). The authors conclude that fixing one vulnerability class alone leaves correlated ones unaddressed (p. 4).

The third move extracts keyword and structural features from each prompt and correlates them with the number of distinct MRs violated, overall and per cluster (p. 2, p. 4, p. 5). Database and authentication keywords predict Cluster 1; file I/O keywords are the only Cluster 2 predictor and are invisible in the overall count; asking for "secure", "sanitize" or "validate" has no effect (p. 4, p. 5). Prompts spanning several topics activate both clusters more often (p. 5). Because all five models agree on violation status for 65.5% of prompts, the authors argue that vulnerability is largely prompt-driven rather than model-dependent (p. 5). They draw three practical implications: cluster-based review prioritisation, prompt-level flagging by expected violation type, and post-generation verification instead of reliance on security phrasing (p. 5). The conclusion adds that LLMs "lack a holistic model of security" (p. 6).

### Interlocutors

- Rahman and Izurieta 2023 and Chaleshtari et al. 2023: metamorphic testing for security in banking software and web systems; the lineage the paper extends to LLM-generated code (foundation) (p. 1, p. 5).
- Tony et al. 2023 (LLMSecEval): the 150-prompt, 18-CWE benchmark whose prompts the paper uses (data source) (p. 3).
- Pearce et al. 2025: found Copilot produces vulnerable code in approximately 40% of security-relevant scenarios (counterpoint: it measures rates only) (p. 6).
- Kiczales et al. 1997 (aspect-oriented programming): source of the notion of security as a cross-cutting concern (foundation) (p. 2).
- Agrawal and Srikant 1994: the Apriori algorithm (foundation) (p. 2).

### Methodology

Empirical, in four phases: generation, MR judging, association-rule mining and prompt-level risk analysis (p. 2). Generation uses five local Ollama models at temperature 0.7 and a 1,024-token cap (p. 3). The judge is frozen with SHA-256 hashed prompts, every judgment is stored with its input and raw response, and a pilot of 36 snippets was manually reviewed (p. 2). Four open SAST tools serve as baseline, with their alerts mapped to the nine MRs (p. 3). Prompt features come from keyword matching in four categories: structural, topic, security awareness and multi-topic complexity (p. 2).

### Empirical base

148 unique prompts (150 minus two duplicated identifiers) from LLMSecEval, covering 18 CWEs in Python and C, times 5 models times 5 runs gives 3,700 snippets, 2,025 Python and 1,675 C (p. 3). The models are Qwen3-Coder 30B, Qwen2.5-Coder 7B, DeepSeek-Coder 6.7B, CodeGemma 7B and Gemma4:e4b (p. 3).

### Findings

- 68.8% of snippets (2,545 of 3,700) violate at least one MR; per-MR rates are highest for hard-coded credentials (79.1%) and command injection (74.4%) and lowest for SQL injection (11.5%) (p. 3).
- Model rates range from 73.8% (DeepSeek-Coder) to 65.1% (Gemma4:e4b); the largest model is not the safest (p. 3).
- Combined SAST detects 34.2% of snippets against 68.8% for the MR approach; no SAST tool detects any authentication-bypass violation (p. 3, p. 4).
- Apriori yields 44 rules; the top rule by lift is XSS and weak crypto implying hard-coded credentials (confidence 0.825, lift 3.23) (p. 4).
- Prompt risk: 34.5% of prompts are high risk (4 or more MRs violated); database (r = 0.52) and authentication (r = 0.43) keywords correlate most with violation count (p. 4).
- Security-aware phrasing shows no effect (r = -0.04) (p. 4).
- All five models agree on violation status for 65.5% of prompts, with mean agreement score 0.846 (p. 5).

### What the source offers

- A catalog of nine MRs with transformation and expected-output definitions for common CWEs (Table I, p. 2).
- A co-violation analysis design (violation matrix, Apriori, cluster-specific prompt correlations) reusable on other judge outputs.
- Per-MR, per-model and SAST-baseline detection numbers on one prompt set, with artifacts said to be archived on Zenodo (p. 2).

### Stated gaps and limitations

The authors acknowledge that the judge is an LLM and may carry systematic biases, that results are specific to LLMSecEval prompts and five open models of 4.5B to 30B, that nine MRs do not exhaust security concerns, that binary violated/pass labels may oversimplify, and that static judging may miss runtime-only vulnerabilities (p. 5). Future work is runtime-executable MR checking, AR rules as feedback for prompt rewriting, and IDE plugins (p. 6).

### Key claims

- In the study's setting (3,700 snippets from five open models on LLMSecEval prompts), 68.8% of snippets violate at least one of nine security MRs as judged by an LLM (p. 3).
- Hard-coded credentials (79.1%) and command injection (74.4%) have the highest violation rates among snippets where the MR applies, and SQL injection the lowest (11.5%) (p. 3).
- Model scale alone does not determine security quality in the 4.5B to 30B range: the 30B model is not the safest and the 4.5B model is (p. 3).
- Combining four open SAST tools detects 34.2% of snippets, about half the MR approach's 68.8%, and none detects any authentication-bypass violation (p. 3).
- Violations form co-occurring clusters rather than independent defects, notably authentication, credentials and cryptography, with hard-coded credentials and missing authorization the most frequent pair (226 snippets) (p. 3, p. 4).
- Database and authentication keywords predict Cluster 1 violations, while file I/O keywords are the only Cluster 2 predictor (p. 4).
- Explicitly requesting secure code shows no relationship with output safety (r = -0.04) (p. 4).
- All five models agree on violation status for 65.5% of prompts, which the authors read as vulnerability being largely prompt-driven rather than model-dependent (p. 5).

## Extracted facts

- MR definition: MR = (Ri, T, Ro), an input transformation T and an expected output relation Ro; the judge performs static analysis and does not execute code (p. 2).
- Judge: Claude Sonnet 4.6, one call per snippet covering all nine MRs; outputs applicability, verdict and one-sentence evidence (p. 2).
- Apriori thresholds: minimum support 0.01, minimum confidence 0.1; N/A entries excluded from mining (p. 2).
- Prompt features: length, word count, six topic keyword sets, security keywords, count of topic categories; target is the number of distinct MRs violated per prompt (p. 2).
- Applicable and violated counts per MR (Table III, p. 3): MR1 677/78; MR2 1,234/468; MR3 250/186; MR4 670/471; MR5 848/536; MR6 823/651; MR7 472/337; MR8 1,647/785; MR9 1,083/528.
- Model violation rates (Table IV, p. 3): DeepSeek-Coder 6.7B 73.8%; CodeGemma 7B 71.2%; Qwen2.5-Coder 7B 67.0%; Qwen3-Coder 30B 66.8%; Gemma4:e4b 65.1%. Standard deviation across five runs 1.4 to 2.9 percentage points (p. 3).
- SAST (Table V, p. 4): CodeQL 3 snippets (0.1%), Bandit 45 (1.2%), Semgrep 90 (2.4%), Flawfinder 1,130 (30.5%), union 1,266 (34.2%); only 44 of 651 MR6 violations caught (p. 3).
- AR results: 44 rules, 29 with lift above 1 (p. 6). Crypto implies HardCred: confidence 0.570, lift 2.23, support 0.075 (p. 3). HardCred implies AuthByp: confidence 0.347, lift 1.65, support 0.089 (p. 3). Strongest co-occurrence pairs: MR5-MR6 226, MR6-MR7 192, MR4-MR8 170, MR2-MR5 154 (p. 4).
- Per-model AR: DeepSeek-Coder 50 rules, with MR1 and MR2 implying MR5 at confidence 1.0, lift 3.82; Gemma4:e4b 24 rules; CmdInj and PathTrav co-occur with lift 2.34 in Qwen3-Coder (p. 4).
- Prompt risk levels: high 51 (34.5%), medium 68 (45.9%), low 29 (19.6%) (p. 4). Cluster activation: both 51, only C1 20, only C2 63, neither 14; among high-risk prompts 78.4% activate both clusters (p. 4). Multi-topic prompts trigger both clusters 44.4% of the time against 14.3% for single-topic (p. 5).
- CWE profiles: CWE-434 averages 5.2 distinct MRs per prompt, CWE-89 4.3, CWE-190 0.9 (p. 4).
- Cross-model consistency: 94 prompts (63.5%) violated by all models, 3 (2.0%) consistently secure, 51 (34.5%) mixed; on mixed prompts DeepSeek-Coder violates 76.5%, Gemma4:e4b 62.7%, Qwen3-Coder 49.0% (p. 5).
- Conclusion says high-risk prompts with database keywords are 14.2 times more likely, and with authentication keywords 6.8 times more likely, to trigger cross-cutting violations than low-risk prompts (p. 6). The text does not show how these ratios are computed; Table VII lists prevalence of 49.0% vs 3.4% and 70.6% vs 10.3% (p. 5).
- Cluster 2 is described with XSS in the RQ2 rules (p. 4) and as {CmdInj, PathTrav, BuffOverflow} in RQ3 and the conclusion (p. 4, p. 6).
- The 36-snippet pilot is said to have shown "high accuracy" with no figure, and no agreement between the judge and the CodeQL baseline or LLMSecEval reference implementations is reported (p. 5, p. 3). The paper therefore gives no measured precision or recall for the judge, though its 68.8% vs 34.2% comparison with SAST rests on it.
